## 三、测试中发现并修复的缺陷

| 编号 | 严重度 | 缺陷 | 根因 | 修复 |
|---|---|---|---|---|
| D1 | **严重** | CutTask 一启动即崩溃（`'float' object is not callable`） | 属性命名为 `self.start`，覆盖了 QThread.start() 方法 | 更名为 `t_start/t_end` |
| D2 | **严重** | 剪切在 Windows 上必然失败（退出码 -22） | 输出文件名含时间冒号 `00:01.00`，Windows 文件名非法字符 | 新增文件名安全的时间格式 `01m23.5s` |
| D3 | 中 | 测试框架收不到任何任务事件 | 跨线程 Qt 队列信号需要主线程泵事件，测试轮询循环缺失 processEvents | 测试框架修复（非产品缺陷） |
| D4 | 低 | 无损剪切测试时长偏差超预期 | 测试视频 GOP 太长（仅 1 个关键帧），关键帧对齐偏差属预期行为 | 测试视频改为 1s 关键帧间隔（产品行为符合设计） |
| D5 | 低 | 断言路径分隔符差异 | json 往返把 `C:/` 规范化为 `C:\` | 测试比较时归一化 |

**历史缺陷回溯**（v1.0 期间发现并修复，回归测试覆盖）：超分子进程 stdout=PIPE 不读取导致管道塞满、引擎卡死在 90%（现统一 DEVNULL + 数输出文件计进度）；社区转换 ncnn 模型与 2022-04 版引擎不兼容（现全部使用官方模型 + 自研转换器以官方权重金标准验证）。

## 五、遗留风险与建议

1. **真人视频速度**：general-x4v3 内部按 4 倍放大再缩回 2 倍，速度比动漫快速模型慢，但已在可用区间（对比 v1.0 的 x4plus 方案快一个数量级以上）。
2. **m3u8 下载不支持断点续跑**：受引擎（N_m3u8DL-CLI）能力限制，属已知边界。
3. **无损剪切**按关键帧对齐是格式本质限制，界面上已明确提示。
4. **VFR（可变帧率）源**合成后理论上可能有轻微音画偏移，主流片源（CFR）不受影响。
5. 建议 v1.2 考虑：恢复任务列表页（当前最多直接展示 3 个可恢复任务）、剪切支持多段拼接。
