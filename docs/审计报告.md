## 六、运营事故分析（2026-09-29 夜）

**现象**：用户一段约 4.4 分钟（7,880 帧）视频在动漫模式 2x 增强至约 58%（4,488 帧）后任务终止，输出目录中成品缺失，v1.0 的失败清理逻辑随后删除了全部临时帧。

**根因分析**：v1.0 设计存在三处叠加风险——① 引擎崩溃/取消后 `finally` 无条件清理临时帧（现场销毁）；② 无任务档案，重启后无法识别半成品；③ 应用运行期未阻止系统睡眠，睡眠唤醒存在 Vulkan 设备丢失导致引擎崩溃的可能（用户当晚正在咨询睡眠问题，时间线吻合但不能完全排除手动取消）。结论：**无论触发路径是哪一条，"失败即销毁现场"都是设计缺陷**。

**已落地的改进（v1.1）**：
1. 失败/取消**不再删除**临时帧与任务档案（仅成功后清理）；
2. 任务档案 JSON 记录源文件/模式/倍数/总帧数，重启后软件自动发现并提示「恢复任务」；
3. 恢复通过硬链接跳过已完成帧，已算部分零重复；
4. 任务运行期调用 SetThreadExecutionState 阻止系统睡眠；
5. 事故的 4,488 帧备份保留于 `backup_frames/`——用户重新下载同一视频后可人工接续，58% 的 GPU 时间可挽回。

**同类事故复发概率评估**：低（崩溃类根因被"保留现场+可恢复"兜底；睡眠类根因被防睡眠机制消除）。

## 七、工程质量审计

- **架构**：界面（PySide6）/引擎（QThread 任务类）分层清晰；统一 BaseTask 信号协议（progress/done/error/cancelled）。
- **健壮性**：音频编码不兼容 mp4 时自动回退 AAC 重编码；Range 请求被拒（200）时自动退回全量下载；416 时清理半成品重下；引擎失败时输出可读的中文错误。
- **可维护性**：转换器、测试套件、打包脚本均可复跑；关键魔法数字（fp16 布局、模型名映射）有注释与验证脚本背书。
- **观察项**（非缺陷）：`m3u8_dl.py` 进度依赖控制台百分比正则，若上游工具改版输出格式需跟进；`settings_tab` 存在未使用的 refresh 占位。

## 八、遗留限制（已向用户披露）

1. m3u8 下载无断点续跑（上游引擎限制）；
2. 无损剪切按关键帧对齐（格式本质）；
3. VFR 片源增强后可能有轻微音画偏移；
4. 真人视频 2x 速度中等（通用模型内部 4x 再缩回）；
5. 若对外分发，FFmpeg GPL 构建触发 GPLv3 义务（自用不受限）。
