# 改进文档：简洁 · 现代化

- **对象**：拾光工具箱 (LUMO) v1.2.0，`app/` 全部界面与支撑代码
- **目标**：把「能用、可靠」的界面升级为「简洁、现代」的界面，同时清掉阻碍观感的正确性缺陷
- **原则**：① 少即是多——能删的控件先删，再谈美化；② 系统一致——颜色/圆角/间距/字号全部出自一套令牌；③ 渐进披露——高级选项默认隐藏，需要时才出现

现状判断：功能与工程质量已经很好（分层清晰、断点续跑、测试齐全），但视觉语言停留在
「白卡片 + 饱和蓝 + emoji 图标」的 2018 年风格，且同一信息在多处重复出现。下面的改动不动任何
引擎逻辑，风险集中在 UI 层。

---

## 一、设计令牌：现代化的地基

现在 `theme.py` 是一份手写 QSS f-string，改一个颜色要改十几处，且没有暗色模式。先把它改成
「令牌 → 生成 QSS」，后面所有改动才有落脚点。

| 令牌 | 现状 | 建议（浅色） | 建议（暗色） |
|---|---|---|---|
| 强调色 | `#4f8cff`（按钮/选中/链接全用它，过重） | `#3478F6`，仅用于主按钮与选中态 | `#0A84FF` |
| 背景 / 表面 | `#f4f6fb` / `#ffffff` + 1px 边框 | `#F5F6F8` / `#FFFFFF`，边框 `rgba(0,0,0,.06)` | `#1C1C1E` / `#2C2C2E`，边框 `rgba(255,255,255,.08)` |
| 正文 / 次要文字 | `#2b2f36` / `#8a93a3` | `#1D1D1F` / `#6E6E73` | `#F5F5F7` / `#98989D` |
| 圆角 | 10 / 14 混用 | 控件 8、卡片 12、浮层 16 | 同左 |
| 间距 | 8/10/12/14/18/20/24/28 混用 | 4pt 网格：8 / 12 / 16 / 24 / 32 | 同左 |
| 字号 | 12/13/14/15/19/21 混用 | 12 / 13 / 15 / 20 四级，行高 1.5 | 同左 |
| 阴影 | 无（全靠边框） | 卡片无阴影；浮层/下拉 `0 8px 24px rgba(0,0,0,.08)` | 浮层 `0 8px 24px rgba(0,0,0,.4)` |
| 动效 | 无 | hover/切换 120–160ms ease-out | 同左 |

配套动作：

1. **暗色模式**：令牌做成 light/dark 两套 dict，QSS 由令牌生成；设置页加「跟随系统 / 浅色 / 深色」。
   跟随系统用 Qt 6.8+ 的 `QStyleHints.colorSchemeChanged`。这是 Win11 用户对「现代」的第一预期。
2. **数字等宽**：进度、大小、速度用 `font-variant-numeric: tabular-nums`（QSS 不支持时就给状态
   QLabel 单独设 QFont），避免下载时文字左右抖动。
3. **标题栏融入**：不改自绘标题栏（成本高），只做两件事——`DwmSetWindowAttribute`
   （`DWMWA_USE_IMMERSIVE_DARK_MODE`）让暗色下标题栏变黑；`setHighDpiScaleFactorRoundingPolicy(PassThrough)`
   修 125%/150% 缩放下发虚。

## 二、界面改造清单

### 2.1 全局：去掉 emoji 图标

导航和界面里的 ⬇️  ✂️ ️ 🖼 🔄 是彩色 emoji，在不同 Windows 版本渲染不一致，且和单色现代风格
冲突。替换为单色线性图标（24px、1.5px 描边、随主题变色），放 `assets/icons/*.svg` 用 `QIcon` 加载：

| 位置 | 现在 | 换成 |
|---|---|---|
| 导航四项 | ⬇️ ✨ ✂️ ️ | arrow-down-to-line / wand / scissors / gear（线性） |
| 封面占位 | 🖼 | image 线性图标，灰色 |
| 恢复横幅 | 🔄 | arrow-path 线性图标 |
| 空状态 | 无 | 48px 线性图标 + 一句文案 |

### 2.2 侧边导航

- 选中态：实心蓝块 → **12% 强调色底 + 强调色文字 + 左侧 3px 圆角指示条**；hover 用 4% 黑/白叠加。
  实心蓝块是全界面最「重」的元素，压过了内容区。
- 删掉 `main_window.py:59` 的 `setFixedHeight(230)`（硬编码，加一项导航或放大系统字号就溢出），
  改为按内容自适应。
- 顶部 logo 区：文字 logo 换成 图标 + 名称 一行，副标题「无损下载 · AI 高清」保留但降到 12px。

### 2.3 下载页（信息重复最多的一页）

- **合并画质/格式控件**：单条网站链接时，解析卡片里已经有画质下拉（`probe_quality`），卡片外那排
  「画质/分辨率 + 保存格式」是重复的。改为：单链接时外层只留「保存格式」，画质只在解析卡片里选；
  批量粘贴时才显示外层画质下拉。一次删掉一排控件和一行说明文字。
- **任务行重排**：现在是「名称 | 200px 悬浮进度条 | 状态文字 | 按钮」四列，进度条像浮在行中间。改为两行式：

  ```
  [图标] 视频标题……………………………………  72%   [取消]
         网站视频 · 128 MB / 350 MB · 3.2 MB/s
         ──────────────────────────── 2px 通栏进度 ────────────────────────────
  ```

  进度条通栏 2–4px 放在行底，百分比右对齐等宽数字；完成后按钮变「打开」并**真的能打开**（见 B1）。
- **空状态**：任务列表空时是一大片白卡 + 底部一行小灰字。改为居中：48px 图标 + 「粘贴链接开始下载」
  + 一个 ghost 按钮「粘贴示例链接」（点击填入一个公开测试直链），空状态本身就是引导。
- **保存位置行**：路径用 13px 次要色 + 省略号，「更改…/打开文件夹」收成两个图标按钮（folder / arrow-out），
  文字按钮留给主操作。

### 2.4 增强页

- 恢复横幅保留（这是产品亮点），但样式换成 warning 令牌（浅黄底 + 黄边），多个可恢复任务收进
  横幅右侧一个「查看全部 (n)」下拉，不再往横幅里塞最多两个额外按钮（`enhance_tab.py:214-220`
  靠 layout 索引增删 widget，脆弱且拥挤）。
- 「处理进度」卡片：进度条 + 当前文件 + 日志列表三层信息压成两层——进度条与当前文件合并为一行，
  日志默认折叠（一行「查看日志 ▸」），失败时自动展开。默认界面立刻安静下来。
- 模式/倍数下拉的说明文字（`_update_hint`）保留，但从常驻一段话改为下拉框下方的 12px 单行提示，
  超长部分进 tooltip。

### 2.5 剪切页

- 「起点/终点」两个输入框 + 两个「设为当前」按钮 → **一个区间选择条**：在播放进度条上叠加可拖拽的
  选区（双柄 RangeSlider，自绘约 80 行），输入框保留为点击选区后弹出的精确值编辑。打点从 4 次点击
  降到 2 次拖拽。
- 输出类型与剪切方式两个下拉合并语义：选「音频」时剪切方式自动隐藏（现在是置灰 + tooltip，
  置灰控件是视觉噪音）。

### 2.6 设置页

- 目录设置与下载页/增强页内的目录行是**同一设置的三个入口**。保留页内入口（上下文相关），设置页
  改为「默认目录」汇总 + 新增「外观」（主题三选）+「关于」。
- 「关于」补版本号与第三方组件版权声明清单（审计报告第五节已建议，CHANGELOG v1.3 已计划），
  版本号读统一来源（见 B3）。

观感的前提是可信。以下四条都是「界面承诺了但没做到」或「状态会串」：

| # | 问题 | 位置 | 修法 |

| B1 | 任务完成后按钮变「打开」但**点了没反应**：`finish()` 断开了 `cancel_clicked` 却从未接打开逻辑，而 README 与空态文案都承诺「完成后点『打开』定位文件」 | `download_tab.py:109-125` | `finish()` 里把按钮改接 `open_in_explorer(结果路径)`；结果路径从 `done` 事件的 `path` 存到 row 上 |

| B4 | 排队中的任务被「清除记录」逻辑漏掉：行被删但线程仍会在槽位空出后**隐形运行** | `download_tab.py:599-617,707-716` | 清除时同步丢弃 `pending` 队列中对应条目；或禁止清除未完成任务 |
| B5 | `except (CancelledError, Exception)` 冗余写法，掩盖意图 | `enhance.py:329` | 改为 `except Exception`（`CancelledError` 本就是其子类） |

## 四、代码层简洁化（让 UI 重构不腐化）

1. **组件去重**：下载页目录行、增强页输出行、设置页 `_path_row` 是同一组件的三份拷贝；三个 tab 各自
   手写进度条 + 状态标签 + 空态。抽 `app/widgets.py`：`PathRow`、`TaskProgressRow`、`EmptyState`、
   `SectionCard` 四个组件，四个页面共用。预计净删 150+ 行。
2. **`app` 变成真包**：现在靠 `main.py` 里 `sys.path.insert` + 平铺 `import theme`，无法 `python -m app.main`，
   也无法被测试以外的工具导入。加 `__init__.py` 改相对导入，`tests` 用包路径导入。
3. **常量集中**：`CREATE_NO_WINDOW = 0x08000000` 在 4 个文件里各写一遍；收进 `paths.py` 或新建 `proc.py`。
4. **日志落盘**：所有子进程 stderr 目前直接 DEVNULL，用户报障时无从查起。统一写到
   `%LOCALAPPDATA%/ShiGuang/logs/app.log`（滚动 3 份），界面保持无感。排障成本从「复现」降为「看日志」。
5. **类型注解**：引擎层（`enhance.py`/`cut_engine.py`/三个下载器）补参数与返回值注解，配合
   `requirements-dev.txt` 加 `mypy` 并在 CI/提交前跑一遍。
